# QuickServe Environment Configuration

This document explains how QuickServe handles environment-specific configuration across local development, the Firebase Emulator Suite, and hosted deployments.

It is a companion to `docs/QuickServe_README_Setup_Deployment.md`, which contains the full setup guide.

---

## 1. Environments

QuickServe has three practical environments:

| Environment | Purpose | Backend |
|---|---|---|
| **Local emulator** | Day-to-day development and automated tests | Firebase Emulator Suite (Auth + Firestore) |
| **Hosted** | Optional deployment of the Flutter Web admin portal | Authorized Firebase project on Spark plan |
| **Production-like review** | Only if separately authorized by the project owner | Authorized Firebase project |

Local emulator mode is the default. No environment should ever reuse production credentials as emulator settings.

---

## 2. Firebase Project Configuration Files

The Flutter apps use generated Firebase config files:

```
apps/mobile/lib/firebase_options.dart
apps/admin/lib/firebase_options.dart
```

These files are generated by the FlutterFire CLI:

```cmd
flutterfire configure
```

They contain the Firebase project ID, API key, app ID, and other public client configuration. **They are not secrets** and are safe to commit.

Do **not** duplicate these values into `.env` files. Do **not** place them in source control as plain text in a shared configuration file that mixes them with private data.

---

## 3. Emulator Mode via `--dart-define`

Flutter does not read `.env` files natively. Environment-specific values are passed at build or run time using Dart defines.

### Enable emulator mode

```cmd
flutter run --dart-define=FIREBASE_USE_EMULATORS=true
```

### Disable emulator mode (use hosted Firebase project)

```cmd
flutter run --dart-define=FIREBASE_USE_EMULATORS=false
```

### Same for Flutter Web

```cmd
flutter run -d chrome --dart-define=FIREBASE_USE_EMULATORS=true
```

### Build Flutter Web for hosting

```cmd
flutter build web --release --dart-define=FIREBASE_USE_EMULATORS=false
```

## 4. Emulator Host and Ports

The default host and ports match `firebase.json`:

| Emulator | Host | Port |
|---|---|---|
| Authentication | `127.0.0.1` (or `10.0.2.2` on Android emulator) | 9099 |
| Cloud Firestore | `127.0.0.1` (or `10.0.2.2` on Android emulator) | 8080 |
| Emulator UI | `127.0.0.1` | 4000 |
| Hosting | `127.0.0.1` | 5000 (optional) |

Override at runtime if needed:

```cmd
flutter run ^
  --dart-define=FIREBASE_USE_EMULATORS=true ^
  --dart-define=FIREBASE_EMULATOR_HOST=10.0.2.2
```

## 5. Reference Template

The file `.env.example` at the repository root lists every environment variable QuickServe expects, with example values. It is a reference only — Flutter does not read it.

Never commit a real `.env` file. `.gitignore` already excludes:

```
.env
.env.local
.env.*.local
```

---

## 6. What Goes Where

| Setting | Where it lives |
|---|---|
| Firebase project ID, API key, app ID, auth domain | `firebase_options.dart` (generated, committed) |
| Emulator on/off flag | `--dart-define=FIREBASE_USE_EMULATORS` |
| Emulator host override | `--dart-define=FIREBASE_EMULATOR_HOST` |
| Emulator ports | `firebase.json` + `--dart-define` overrides |
| Crashlytics enable flag | `--dart-define=ENABLE_CRASHLYTICS` |
| Log level | `--dart-define=LOG_LEVEL` |
| Firebase Admin SDK / service account | **Never committed** — managed outside the repo by the operator |
| Local seed passwords | **Never committed** — supplied through emulator setup or ignored local files |

---

## 7. Security Rules for Configuration

Never commit:

- Passwords
- Authentication tokens
- API keys that are not intended for public client configuration
- Private keys or service-account JSON
- Local seed files containing passwords
- Production environment files containing secrets
- Emulator exports containing sensitive or real data

Use the template and the emulator. If a secret is required for hosted deployment, provide it through the deployment environment — never by pasting it into a committed file.

---

## 8. Local vs. Hosted Checklist

Before running integration tests or hosted deployment, confirm:

- [ ] The selected environment (local emulator vs. hosted) is explicit.
- [ ] The correct `--dart-define` flags are set.
- [ ] Firebase configuration points to the intended project.
- [ ] No production credentials are used as emulator settings.
- [ ] No `.env` file is staged for commit (`git status` confirms).
- [ ] The emulator is running if `FIREBASE_USE_EMULATORS=true`.

---

## 9. Summary

- Use `--dart-define` for runtime configuration.
- Use `.env.example` as a reference, not as a real configuration source.
- Use `firebase_options.dart` for Firebase project wiring.
- Never commit secrets.
- Keep emulator configuration separate from hosted configuration.
